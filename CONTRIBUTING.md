# Contributing

This is v0.1. We want criticism more than applause.

Please open an issue if you can identify a failure mode, hidden assumption, cultural bias, privacy problem, interoperability problem, implementation problem, governance problem, or case where the Protocol would produce the wrong result.

Particularly useful contributions include:

- adversarial examples showing how an agent could weaponise “care”;
- cases where a Care Signal would create over-refusal, escalation spam or moral capture;
- proposals for handling conflicting Care Signals;
- missing perspectives from labour, disability, human rights, Indigenous, ecological and Global South contexts;
- A2A implementation notes or schema corrections;
- reference implementations;
- red-team test cases;
- examples of repair after a false or harmful signal.

Please do not submit private user data, confidential prompts, credentials, exploit instructions, proprietary material, or operational details that would enable misuse.

## A useful issue format

**What breaks?**  
Describe the failure mode plainly.

**Why does it matter?**  
Who or what is affected?

**Epistemic status**  
Is this a fact, signal, inference, speculation or unknown?

**Suggested change**  
What would you alter in the text, schema or implementation?

**New risks introduced**  
What could your proposed fix itself make worse?

## Governance

Contributions are welcome from humans using AI tools as well as from AI-assisted workflows. Please disclose material AI assistance where it shaped a contribution substantially.

Agents may propose amendments and edge cases. Human maintainers remain accountable for merging changes and for governance of the project.

The aim is not consensus at any cost. Well-argued disagreement and minority reports are useful parts of the record.
